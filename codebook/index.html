Public Codebook

Operational definitions for review.

The codebook defines how Campus Evidence Lab labels public-source records. It is a review tool, not a ranking system, safety score, prevalence estimate, or legal finding.

What It Covers

  • Event categories and when not to use them.
  • Affected-community labels and source-support requirements.
  • Verification, confidence, source type, and date precision rules.
  • Legal-status and institutional-response wording limits.
  • Exclusion rules and common reviewer mistakes.

Reviewer Use

Use the codebook to check whether a record can be reproduced from public sources. If a label is not supported, the record should be narrowed, corrected, lowered in confidence, queued for review, or excluded.

Affected-Community Taxonomy Note

The current dataset uses one affected-community field that mixes broad protected-category labels with narrower source-identified identities. Reviewers should treat the field as source-identification, not legal classification. The intended next refinement is a two-tier model: broad protected area plus narrower affected identity when supported by source text.

Sexual orientation and gender identity may overlap with sex-discrimination law, but reviewers should break them out as separate documentation labels when public sources support that distinction. Use LGBTQ+ only when the source itself uses a broader grouped label or when a narrower label would not be reproducible from the source.

Political belief, viewpoint, and ideology are not standalone affected-community labels in the MVP. Zionist, anti-Zionist, Israel-policy, Palestinian-advocacy, or other ideological language should not be converted into a protected-community label unless public sources support that framing; ambiguous records go to broad-label review.

False or Disputed Allegations

If public sources later state that an allegation was false, unfounded, withdrawn, fabricated, or a hoax, the record must be corrected rather than preserving the allegation unqualified. Reviewers should attach the corrective public source, attribute each source's posture, update confidence or verification when needed, and record the change in the changelog.
