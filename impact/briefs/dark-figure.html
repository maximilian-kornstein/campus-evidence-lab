The Dark Figure

Estimating Unreported Antisemitic Hate Crime with Bayesian Record Linkage and Multiple-Systems Estimation

In one line

By checking which antisemitic incidents turn up on more than one incomplete list, we can estimate how many incidents every list missed, and say honestly how unsure that estimate is.

The problem

Debates about antisemitism are argued in counts, yet every count is partial. For 2025, the FBI’s police-based statistics listed 1,528 anti-Jewish hate-crime incidents, while the ADL’s audit, which also counts non-criminal harassment, listed 6,274: different filters on the same reality, not rival answers. Incidents go missing when victims do not report, police do not record a bias motive, or agencies do not submit data, so a rising or falling count can reflect reporting as much as hate. If missing incidents cluster where victims trust institutions least, resources allocated by recorded counts miss the communities most affected, Jewish or otherwise.

What we built

  • Comparing overlapping lists. Police, NGO audits, community-security groups and reporting portals each record some of the same incidents. The pattern of overlap carries information about the incidents all of them missed (“capture–recapture”, already used to estimate conflict casualties and victims of modern slavery).
  • An honest “what-if” dial. One key assumption about how the lists relate to each other can never be tested from the data. We turn it into a single adjustable setting and report the range of answers it allows, in both directions, rather than one confident number.
  • Fixing known distortions. Some lists copy others (an audit may take in police reports); recording where each record came from removes that bias. Lists share no ID number, so records must be matched by date, place and type, and we model how matching mistakes distort the result.
  • A reporting funnel. We split the path from incident to federal statistics into stages (reported, recognised as bias-motivated, submitted), so a gap between two places can be traced to where incidents are lost. Incidents never reported to anyone can only be estimated with victim surveys.

What our simulations show

All results come from computer-simulated data with a known true answer (2,000 invented incidents, four invented lists).

  • The theory’s warnings held up. When some incidents were far less visible than others, the classic two-list estimate came out about 39% too low. When one list copied half of another’s records, using each record’s source flag cut the error from about −39% to about −1%.
  • The “what-if” ranges worked, but were wide. At the wider setting they contained the true number of missed incidents in 87–98% of simulated datasets, but in one scenario the typical range ran from about 230 to 1,680 when the truth was about 620. Without outside knowledge to narrow the dial, ranges this wide cannot guide policy.
  • Our correction for matching errors failed under realistic errors. It worked when errors followed its simplified model, but with realistic typos and date slips most errors were “swaps” (a record matched to the wrong partner), which that model leaves out. The correction then made things worse (about 47% too high, against 40% uncorrected), and averaging over many possible matchings did not remove the bias either, so we use it only as a warning light.

What this is not

StatusA methods paper, with no real-world findings. No actual incident counts have been measured yet, and no real records have been linked. Every result here comes from simulated data; the FBI and ADL figures are published counts, quoted for context. The paper proposes how to measure these numbers responsibly.

What would come next

A pilot for New York City, 2024–2025, linking police, NGO, community-security and reporting-portal records under data-use agreements, ethics review and privacy-protecting linkage, with the analysis plan and code registered publicly before any real record is accessed. If its checks show the lists cannot support a reliable estimate, we will report that as prominently as we would an estimate.
